C1 evidence: first headless import on a fresh checkout (review finding M1)
godot 4.7.2.stable.official.ed1daf0bf    HEAD fed8002 (the C1 work is uncommitted in the working tree)

Problem (found by the C1 review): with no godot/.godot (a fresh checkout), the first `godot --headless --import` loads the GDExtension class
SwarmNative during its first filesystem scan and then crashes while shutting down (SIGSEGV, shell exit code 134). Godot 4.7.2 editor behaviour,
intermittent.
Fix: tools/lib/godot_project.sh, swarm_seed_extension_list "$PROJECT_DIR": if godot/.godot/extension_list.cfg does not exist, it is created with one
line per *.gdextension file of the project (today: `res://swarm_native.gdextension`). tools/run_godot_tests.sh calls it after the native build and before the
first Godot start; tools/build_android.sh calls it after the native build and before tests/import/export (so --skip-tests --skip-import also profits).
An existing extension_list.cfg is never touched; the editor maintains it from then on (the file the editor writes is the same one line).

How a fresh checkout is made (every run, <scratch>/fix/fresh_lib.sh): a new directory, filled from
  git ls-files -co --exclude-standard -z | tar --null -T - -cf - | tar -xf - -C <dir>
= the 367 files of the working tree that git would track (committed + untracked-not-ignored), so no godot/.godot, no godot/bin (libraries), no
export/. The run builds the libraries itself (tools/build_native.sh --host-only --debug-only inside run_godot_tests.sh; objects of godot-cpp come
from the shared cache, the clone's own 4 sources are compiled: "built in 1-2s"), so the libraries exist when the first import starts.
