2. Where Godot 4.7.2's non-Gradle exporter puts the GDExtension (found by exporting, not assumed)
----------------------------------------------------------------------

Export of godot/swarm_native.gdextension with the preset "Android" (architectures arm64-v8a + armeabi-v7a), `--export-debug`:
  lib/arm64-v8a/libswarm_native.android.template_debug.arm64.so      <- godot/bin/libswarm_native.android.template_debug.arm64.so (android.debug.arm64)
  lib/armeabi-v7a/libswarm_native.android.template_debug.arm32.so    <- godot/bin/libswarm_native.android.template_debug.arm32.so (android.debug.arm32)
  assets/swarm_native.gdextension                                    <- the descriptor, byte-identical
So the exporter picks the "android.debug.<arch>" entries for a debug export, maps arch to ABI folder (arm64 -> arm64-v8a, arm32 -> armeabi-v7a),
and keeps the file name. Nothing needed to be added to export_presets.cfg: the libraries are packed automatically, "stored" (not deflated), which
keeps zipalign -P 16 happy. Neither the Linux libraries nor the unused-ABI libraries are in the APK. The android.release.* entries are what a
`--export-release` would pick up (not exercised in C1; the release libraries are built and checked).
Godot's own template already ships lib/<abi>/libc++_shared.so and libgodot_android.so; our libraries do not depend on libc++_shared.so
(NEEDED: libm.so libdl.so libc.so only), they carry their own static libc++.

5. Earlier failures that led to the current state
----------------------------------------------------------------------

- First android build (before the static libc++ link flag): build_native.sh failed "unexpected shared dependency: libc++_shared.so" for both arm64
  targets, because the NDK's clang++ links libc++ dynamically by default. Fixed in native/SConstruct (-static-libstdc++ -Wl,--exclude-libs,ALL).
- First android build, arm32: the check wanted vmul.f64 + vadd.f64 and found vmla.f64 (chained multiply-accumulate, not fused; see build.txt
  section 5). The accepted arm32 forms are now vmul+vadd or vmla; the fused vfma/vfms/vfnma/vfnms stay forbidden.
