## 仕様からのずれ（実装時に判断されたもの。すべて受け入れる）

1. LGPL の条項番号：仕様書の §2(a) は誤りで、§2(b) が正しい（LGPL 本文で確認）。仕様書を訂正した。
2. 受け渡し層の `randi` / `randi_fx` は、引数が ±2^31 を超えると `push_error` を出して 0 を返す（乱数は引かない）。C++ 本体の前提条件を、スクリプトから破れないようにするためである。
3. `SwarmGameRng.shuffle` は、要素を一時配列に写して並べ替え、書き戻す。godot-cpp の `Array` には連続した領域への書き込み口がないためである。並べ替えた結果と乱数を引く回数は同じである。
4. `POW2` 表はコンパイル時の定数にした。`SINCOSTAB` は、引くたびにビット列から double に変換する。値は同じである。
5. `GameRng::shuffle` は、自分自身との交換を省く。結果は同じである。

## 記録しておく注意点（修正はしない）

| 項目 | 内容 | 扱い |
| --- | --- | --- |
| ヘッダーだけの乱数クラス | `seeded_rng.h` などは、ライブラリとテストプログラムで別々にコンパイルされる。そのため「同じ機械語を試験する」という性質は、`sim/*.cpp` の部分にしか当てはまらない。乱数部分は、同じソース・同じコンパイラー設定で作った別のコピーを試験している | C3 で戦闘処理を `.cpp` に移すときに、改めて判断する |
| GDScript 版の直接の照合がなくなった | ユーザーの判断（C++ 版だけ）による。GDScript 版 `JsMath` と乱数は C3 まで使われる。参照トレース7本の照合と `check_js_compat_consts.mjs` が、間接的に守る | C3 で GDScript 版を消す |
| `js_compat.gd` に著作権表示がない | 【事実】glibc（LGPL）と fdlibm の表示がない | 記録だけ（ユーザーの判断）。C3 で GDScript 版を消す |
| `randi` の範囲の検査 | デバッグ版の C++ 本体では、範囲外の引数で異常終了する。この経路は試験していない | C3 で戦闘処理から呼ぶ箇所は、範囲内の値だけを渡す |
| qemu の限界 | qemu-user は ARM の命令を再現するが、実機の FPU の設定は確かめられない | S9（実機） |
| qemu がない場合の失敗 | `build_native.sh` のこの分岐は実際には試していない（`cpp_toolchain.sh` が先に止めるため、到達しない） | このままでよい |
