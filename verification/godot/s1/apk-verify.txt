3. Notes
----------------------------------------------------------------------
- apksigner: "v1 scheme: false" in the default run is because the manifest has minSdk 24 (apksigner
  skips JAR signing there). With --min-sdk-version 23 the v1 signature also verifies, so META-INF/* is valid.
  v3.1, v4 and SourceStamp are false (v4 needs a separate .idsig; not used).
- Permissions: NO <uses-permission> element and no app-declared <permission> element; `aapt2 dump permissions`
  lists none (no INTERNET). The gate in build_android.sh checks the manifest (xmltree) and the badging output; the
  AndroidX "<package>.DYNAMIC_RECEIVER_NOT_EXPORTED_PERMISSION" (not present here) would be a WARN, anything else a FAIL.
  The manifest contains two permission-related ATTRIBUTES, both from the prebuilt Godot 4.7.2 template,
  neither is a permission request:
    * <receiver androidx.profileinstaller.ProfileInstallReceiver android:permission="android.permission.DUMP">
      guards the receiver (only callers holding DUMP, e.g. adb shell, may send it intents). It requests nothing.
    * <provider androidx.core.content.FileProvider android:grantUriPermissions="true" exported="false">
      is the standard FileProvider flag (URI grants), not a manifest permission.
- SDK levels: minSdkVersion 24 and targetSdkVersion 36 are the template defaults of Godot 4.7.2
  (DEFAULT_MIN_SDK_VERSION 24, DEFAULT_TARGET_SDK_VERSION 36). The non-Gradle export cannot change them.
  This answers the open question in design 10 item 3 / section 12.
- screenOrientation=13 (fullUser) is reported as WARN. Design 6.1 and fg.4 use fullSensor (10). Godot 4.7.2's
  prebuilt-template exporter writes 13 for "Sensor" (per a review of the 4.7.2 source, gradle_export_util.cpp: SCREEN_SENSOR -> 13), which allows all
  four orientations but follows the system rotation lock, so this cannot be fixed through project settings.
  DECISION FOR THE USER: accept fullUser, or plan a Gradle build / manifest override in S9.
- WARNING (Godot 4.7.2 exporter behaviour, found during this check): both <provider> elements,
  androidx.core.content.FileProvider and androidx.startup.InitializationProvider, carry the same authority
  "com.elementalswarm.engine.fileprovider". In the unmodified template they differ
  (com.godot.game.fileprovider / com.godot.game.androidx-startup). Cause: export_plugin.cpp rewrites the
  "authorities" attribute of every <provider> to "<package>.fileprovider". Possible effect (UNVERIFIED, no device
  here): Android registers only the first provider with a given authority, so the AndroidX startup initializer
  (ProfileInstaller) may not be registered. Install failure is not expected for a same-package duplicate, but this
  has not been tested. tools/build_android.sh reports it as WARN. A Gradle build (design 12) would avoid it.
- Reproducibility: main.tscn now carries unique_id= on every node. Without them Godot invents random node ids on every
  clean import, so main.scn, assets.sparsepck and META-INF differed between two clean builds of one commit. After the
  fix two clean builds (rm -rf godot/.godot between them) have identical content in every zip entry.
- Side effects: the script runs Godot (and with it adb) with HOME, TMPDIR and XDG_DATA_HOME inside the cache dir and
  adb on the private port 5199. ~/.android and /tmp/adb.<uid>.log were not touched by the final build, and a
  developer's adb server on tcp:5037 survived a build (tested with a throwaway server).
- The APK has not been installed or run on a device or emulator (design 9.5).
