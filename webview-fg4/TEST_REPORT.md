# Elemental Swarm Android fg.4 検証報告

作成日時: 2026-10-19T11:28:37+09:00

## Work Performed / 実施内容

- 添付fg.3を基準として、固定更新、描画、敵探索、HUD、Worker、Android側の構成を確認しました。
- 地形・光彩・被弾点滅アトラス・縮小エフェクト・属性範囲画像のうち、作成後に変更しないCanvasを明示的に登録して共有します。
- 動的な光源マップや一般のCanvasは引き続きフレームごとに独立して複製します。共有画像は保持フレームの参照がなくなってから破棄します。
- 描画状態とパスは変更時にコピーし、既に記録した描画が後から変更されない構造にしました。
- 並進変換の簡略化、描画順とパスの準備の再利用、移動履歴の再利用、分位値の必要時集計、UIの重複書き込み削減を行いました。
- 非可逆な変換・極小スケール・微小な差の扱いは元の処理を保持し、境界ケースを追加検証しました。
- アプリID・署名鍵を継続し、versionCodeを1111195、versionNameを11.11.9-fg.4に更新しました。

## Verified / 性能比較

測定ブラウザー: Chromium 141.0.7390.37 / Linux、390×844 CSS px、DPR 3、deviceMemory=4のモバイル条件です。
GPU描画はSwiftShaderによるソフトウェア処理です。Androidの端末GPUを測定した結果ではありません。
Workerを両版ともOFFにし、同じfixtureをfg.3→fg.4→fg.4→fg.3の順で実行しました。
各版・各条件につき24組のウォームアップ後に80組を2回、合計160組を測定しています。
各組は新規に実フレームを記録し、次の組までrequestAnimationFrameを待ちます。

以下は移動履歴の観測＋実フレーム記録＋中間フレーム合成のコールバック経過時間です。
ブラウザー内部の描画待ちやOSのスケジューリングも時間に含まれます。短縮率はCPU側の処理時間の比較です。

| 軽量 | 固定 | 1.20 | 1.10 | 8.3% | 2.00 → 1.70 |
| 軽量 | 移動 | 0.70 | 0.70 | 0.0% | 1.50 → 1.40 |
| 自動 | 固定 | 2.70 | 2.00 | 25.9% | 4.50 → 3.10 |

軽量設定では差が小さく、全条件で同じ短縮率を得られる結果ではありません。
大量配置は敵45体、味方弾229発、敵弾212発、経験値オーブ220個の制御された場面です。
P95は遅い側の処理時間を確認するため併記しています。
大量配置の最高画質では依然として長い待ち時間が残っています。
同条件の追加CPUプロファイルではdrawImage/strokeなどブラウザー内部の描画が時間の多くを占めました。

通常描画OFFの比較は、ゲームの更新と描画を含むコールバック全体です。
各版・各画質で200コールバックを測定し、戦闘状態も比較しました。

| フレーム生成OFF | 中央値 ms（fg.3 → fg.4） | P95 ms（fg.3 → fg.4） | 戦闘状態 |
| --- | ---: | ---: | --- |
| 自動 | 0.60 → 0.50 | 1.30 → 1.30 | 一致 |
| 最高 | 0.90 → 0.90 | 2.70 → 1.50 | 一致 |

制御場面では、複製した画素数が地形・光彩を含めて0になりました。
共有後も地形や画像そのものは必要なため、これはアプリ全体のメモリー使用量が0という意味ではありません。
動的Canvasを固定する機能と画像予算超過時の安全な復帰は維持しています。
